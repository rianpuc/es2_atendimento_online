6. Código do Backend Autêntico (Java / Spring Boot)

Código real elaborado pelo grupo conectando a estrutura de Controllers da API REST e garantindo regras de negócio, como validação de exclusão em cascata.

DEV 1 - Gustavo ProfissionalSaudeController.java

@RestController @RequestMapping("/api/profissional") @CrossOrigin(origins = "*") public class ProfissionalSaudeController { private final ProfissionalSaudeRepository repository; @Autowired private AtendimentoRepository atendimentoRepository; public ProfissionalSaudeController(ProfissionalSaudeRepository repository) { this.repository = repository; } // CREATE @PostMapping public ResponseEntity<ProfissionalSaude> criar(@Valid @RequestBody ProfissionalSaude profissionalSaude) { ProfissionalSaude salvo = repository.save(profissionalSaude); return ResponseEntity.status(HttpStatus.CREATED).body(salvo); } // READ @GetMapping public ResponseEntity<List<ProfissionalSaude>> listar() { return ResponseEntity.ok(repository.findAllByOrderByNomeAsc()); } // READ (ID) @GetMapping("/{id}") public ResponseEntity<?> buscar(@PathVariable Long id) { return repository.findById(id).map(ResponseEntity::ok).orElse(ResponseEntity.notFound().build()); } // UPDATE @PutMapping("/{id}") public ResponseEntity<?> atualizar(@PathVariable Long id, @Valid @RequestBody ProfissionalSaude dados) { return repository.findById(id).map(profissional -> { profissional.setNome(dados.getNome()); profissional.setEndereco(dados.getEndereco()); profissional.setTelefone(dados.getTelefone()); profissional.setCategoria(dados.getCategoria()); return ResponseEntity.ok(repository.save(profissional)); }).orElse(ResponseEntity.notFound().build()); } // DELETE (Impede excluir caso possua atendimentos!) @DeleteMapping("/{id}") public ResponseEntity<?> deletar(@PathVariable Long id) { return repository.findById(id).map(profissional -> { List<Atendimento> atendimentos = atendimentoRepository.findByProfissionalSaudeId(id); if (!atendimentos.isEmpty()) { return ResponseEntity.badRequest().body(Map.of("erro", "Não é possível excluir um profissional com atendimentos vinculados")); } repository.delete(profissional); return ResponseEntity.ok(Map.of("mensagem", "Profissional removido com sucesso")); }).orElse(ResponseEntity.notFound().build()); } }

7. Código do Frontend Autêntico (React)

O time configurou de forma inteligente o Axios (api.js) que resolve automaticamente a URL do Render via resolveApiUrl().

Serviço Axios (api.js)

import axios from 'axios'; // Resolve a URL base da API dinamicamente (Localhost ou Render) function resolveApiUrl() { const raw = process.env.REACT_APP_API_URL; if (!raw) return 'http://localhost:8080/api'; let url = raw.trim(); if (!/^https?:\/\//i.test(url)) url = `https://${url}`; url = url.replace(/\/+$/, ''); if (!/\/api$/i.test(url)) url = `${url}/api`; return url; } const api = axios.create({ baseURL: resolveApiUrl() }); // ========== SERVIÇOS EXPORTADOS ========== export const profissionalSaudeService = { listar: () => api.get('/profissional'), deletar: (id) => api.delete(`/profissional/${id}`), /*...*/ } export const atendimentoService = { listar: () => api.get('/atendimento'), gerarLink: () => api.get('/atendimento/gerar-link'), deletar: (id) => api.delete(`/atendimento/${id}`), /*...*/ }; export const examesService = { listar: () => api.get('/exames'), deletar: (id) => api.delete(`/exames/${id}`), /*...*/ };

10. CI/CD Pipeline (Separados com GitHub Actions)

CI WORKFLOW CD WORKFLOW via HOOKS
Garantia de Qualidade: Seguindo boas práticas de isolamento de pipelines, criamos dois arquivos distintos. O arquivo deploy.yml só é ativado quando o arquivo ci.yml termina com 100% de sucesso na branch master.

Arquivo 1: .github/workflows/ci.yml

name: CI on: push: branches: [ master ] jobs: build-and-test: runs-on: ubuntu-latest services: postgres: image: postgres:15 env: POSTGRES_DB: atendimento_test POSTGRES_USER: postgres POSTGRES_PASSWORD: postgres ports: [ "5432:5432" ] steps: - uses: actions/checkout@v4 - name: Setup Java uses: actions/setup-java@v4 with: { java-version: '17', distribution: 'temurin' } - name: Run Backend Tests run: mvn test -B working-directory: ./backend - name: Setup Node.js uses: actions/setup-node@v4 with: { node-version: '20' } - run: npm ci && npm test -- --watchAll=false working-directory: ./frontend

Arquivo 2: .github/workflows/deploy.yml

name: Deploy to Render on: workflow_run: workflows: ["CI"] types: [completed] branches: [master] jobs: trigger-deploy: runs-on: ubuntu-latest if: ${{ github.event.workflow_run.conclusion == 'success' }} steps: - name: Trigger Render Deploy Webhooks via cURL POST env: HOOK_BACK: ${{ secrets.RENDER_DEPLOY_HOOK_BACK }} HOOK_FRONT: ${{ secrets.RENDER_DEPLOY_HOOK_FRONT }} run: | echo "Disparando Gatilho Automático do Backend no Render..." curl -X POST "$HOOK_BACK" echo "Disparando Gatilho Automático do Frontend no Render..." curl -X POST "$HOOK_FRONT"

12. Deploy no Render (Produção)

LIVE ON RENDER

Configuração do Monorepo no Painel do Render:

  1. Serviço de Banco de Dados: Criado uma instância do Render Managed PostgreSQL. O Render gera automaticamente uma string global em `Internal Database URL`.
  2. Serviço de Backend (Web Service):
    • Root Directory definido como: backend
    • Build Command: mvn clean package -DskipTests
    • Start Command: java -jar target/app.jar
    • Vá na aba Environment e crie uma variável chamada SPRING_DATASOURCE_URL vinculando a URL gerada pelo banco.
  3. Serviço de Frontend (Static Site):
    • Root Directory definido como: frontend
    • Build Command: npm run build
    • Publish Directory: build (ou dist dependendo do setup)
